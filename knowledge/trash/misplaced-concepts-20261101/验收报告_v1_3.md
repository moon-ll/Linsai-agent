  # 多报告交叉一致性验收协议

  ## 林赛的理解

  我做 PI 这些年最深的体会是：大型文献调研最大的风险不是"漏读"，而是**同一事实在不同文档里写法不一致**——一处写 GHz、一处写 THz，审稿人和评审专家一眼就能抓住。这份验收报告 v1.3 给我的启发在于，它把"验收"从一句"看起来不错"变成了一套可逐项打勾的协议：7 项标准、独立 subagent 验收、再加上横跨 5 个课题方向（T1 量子几何 / T2 能谷 / T3 能带 / T4 序参量 / T5 反演方法学）的交叉验证。

  我特别认同其中两条纪律。一是**诚实标注**——没调研到就是没调研到，单列"诚实清单"（39 项），这比含糊带过更能赢得信任。二是**跨报告一致性作为一等公民标准**——6 大协同核心发现在 20+ 份文档中"完全一致"被单独列为验收项，而不是默认成立。我自己的课题组写申请书时，参考文献格式统一、关键数据回链核对、未覆盖领域明示，这三件事值得固化成流程。

  ## 核心要点

  - **验收对象分层**：立项报告（5 份 v1.2）→ 展板（5 份 v1.2）→ 精读文档（11 份、98 篇）→ 立项依据 v0.1+深度精读（4 份）→ Q1+Q2 升级文档（5 份），一层不漏。
  - **7 项验收标准**：
    1. 论文真实性（100% arXiv/DOI 可溯源，1992–2026 全时段）
    2. 数据准确性（精读中的关键数据与立项依据严格一致，多轮交叉验证）
    3. 诚实标注（未调研到项明确列出，5 报告共 39 项）
    4. 结构完整性（5 节 + 附录 A/B/C/D）
    5. 参考文献格式标准（作者+期刊+年份+DOI/URL，跨报告无重复 arXiv ID）
    6. 公式 LaTeX 规范（$$ 块 + 公式编号）
    7. 跨报告一致性（协同发现、引用、关键数据、合作契机 100% 一致）
  - **5 段精读模板**：作者+期刊+年份+DOI+URL 的固定格式，是格式标准能执行的前提。
  - **附录体系承载诚实性**：附录 A 收"未调研清单"，附录 B/C 收补充与深度精读，附录 D 收升级记录——验收的每一项都有文档锚点。
  - **验收结论"全优秀"建立在量化清单上**：字节数、行数、篇数、字数增量全部入表，可复核而非凭印象。

  ## 实验/研究关联

  - 对应我课题库里申请书"整篇一致性审查（full_review）"模块的方法论原型：把跨文档一致性从"感觉"变成"7 项打勾"。
  - "关键数据 ↔ 立项依据 ↔ 立项报告"的三方回链核对，可直接迁移到课题组内部的文献笔记—申请书数据一致性检查。
  - 独立 subagent 验收模式（验收者不参与生产）与我的评审团三角色互不锚定设计同源：评审独立性是结论可信的前提。
  - 30+ 国内合作组清单的跨报告一致维护（11+11+10+18+11 个提及，含重复），提示合作网络信息本身也需要单一真相源 + 多处引用，而非多处各自维护。

  ## 开放问题

  - ~10 篇论文 web_extract timeout 失败（部分 arXiv ID 未成功抽取），真实性与数据准确性对这批文献的覆盖是否打折，需追踪补救。
  - 独立 subagent 验收 v1.0 模式的具体打分/否决机制，本摘要未给出，值得回读验收标准原文。
  - "验收全优秀"与后续申请书实际评审结果之间的相关性，尚无反馈数据闭环。
