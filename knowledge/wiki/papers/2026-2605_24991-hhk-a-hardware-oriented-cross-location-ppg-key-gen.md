• # HHK：面向硬件的跨位置 PPG 密钥生成架构

  ## 林赛的理解

  这篇工作属于可穿戴生物特征安全领域，核心是把跨身体位置的光电容积脉搏波（PPG）心跳间期（IBI）提取、对齐、量化与极化码模糊承诺整套流程做到可综合 RTL 并在 FPGA 上验证。它离本组直接关心的强场超快光学、HHG 光谱学与阿秒物理相当远，因此我不会把它纳入选题池或文献综述主线。但其方法论层面有两处可迁移的价值：一是把“带噪声的连续时间生理信号”转换成“低 bit 一致性情报”并做硬件级纠错，这种“信号→特征→量化→纠错→密钥”的 pipeline 对设计强场实验里的实时前端触发/门控逻辑有启发；二是论文对“野外真实数据 vs 实验室受控数据”性能崩落（key agreement 从 90%+ 掉到 51–70%）的坦诚量化，恰好提醒我们在 HHG/阿秒领域做算法验证时，也必须在真实束线噪声、样品抖动和限能条件下测试，而非只在干净仿真里宣称指标。此外，它用纯定点、无乘法器、无 DSP/BRAM 的硬件实现路径，对我们未来把某些光谱诊断模块（如单像素平衡探测、时频分析前端）往低功耗 ASIC 或边缘 FPGA 下沉时，有功耗与面积估算的参照意义。

  ## 研究问题

  论文要解决的核心问题是：如何在资源极度受限的可穿戴体域网（BAN）节点上，实现一对位于不同身体部位（head/wrist/ankle）的设备在不传输任何秘密的前提下，从同步采集的 PPG 信号中独立推导出一致的会话密钥。具体而言，它追问三个子问题：跨部位 PPG 波形差异和真实运动伪影是否仍允许足够高的 IBI 时序一致性；如何用纯硬件（可综合 RTL）完成 IBI 提取、对齐、量化与纠错；以及该硬件架构在真实自由生活（ambulatory）数据上的密钥一致率、面积和功耗是否满足 BAN 能量预算。

  ## 研究背景

  体域网（BAN）连接可穿戴/植入式节点用于连续健康监测、运动追踪和闭环治疗，其无线链路必须频繁建立会话密钥以保证前向安全。然而公钥密码学对深度受限的生物医学节点而言计算和能耗过高；对称预分发方案在被攻破后则失去前向安全。基于生理信号（尤其是同一人体内的 PPG）的密钥生成成为替代方案：两节点同时观测同一心脏节律，无需传输密钥即可独立生成匹配密钥。已有工作如 H2K（ECG/PPG，实验室 MIT-BIH/测试平台）、FaceFinger（PPG，手指–面部）、E2P（ECG 放大级联）、MagKey（BCG，腕部–腕部）、PPG Token（手指/腕部）等均在软件层面、受控或静止条件下验证。这些工作存在两个关键缺口：一是缺少在真实自由生活（ambulatory）条件下跨多个身体部位的验证；二是全部依赖主机处理器上的软件实现，无法直接部署到无通用处理器的超低功耗自治节点。同时，近期研究表明液晶调制器可合成任意 PPG 波形，对商品化 PPG 传感器实现 91.2% 的身份欺骗成功率，进一步加剧了对真实场景下安全方法的需求。在此背景下，HHK 旨在同时填补“多位置野外验证”和“可综合 RTL 硬件实现”两个缺口。

  ## 研究方法

  ### 数据集
  使用 WildPPG 数据集（NeurIPS 2024），该数据集在一次真实登山探险中于瑞士少女峰（海拔 3,460 m）采集。16 名受试者佩戴同步 PPG 和 IMU 传感器，平均连续记录 13.5 小时（最短 12.3 小时），总计 216 小时。受试者进行完全自由生活活动：雪地行走、进入零下冰洞、多次以最快速度爬楼梯、用餐、乘坐小型货车（单程 140 min）、缆车和山地火车。环境包括低温、高海拔和变化日照。论文使用 head、wrist、ankle 三个通道，排除 sternum 通道（胸骨处 PPG 在运动下 beat 可见性不足）。

  ### 信号处理与对齐
  - 采样率：128 Hz，16-bit PPG。
  - 预处理：因果定点 IIR 带通滤波器，Q15 定点（16-bit 有符号，15 位小数），无乘法器实现。
  - 节拍检测：局部最大值检测器，候选峰值需超过固定 prominence 阈值，并与上一次检测相隔至少 150 BPM 对应的不应期（400 ms）。
  - IBI 计算：$IBI_n^{(s)} = t_{n+1}^{(s)} - t_n^{(s)}$。
  - 跨位置对齐：对 A 位置每个 beat 时间戳，在 300 ms 容差内找 B 位置最近 beat，仅保留匹配对。
  - 量化：将 IBI 按全数据集四分位数划分为 4 个等频 bin，每个 IBI 映射为 2-bit Gray 码，保证边界跨越时最多 1-bit 不一致。
  - 运动门控：120 s 窗口内基于 IMU 幅值标准差进行运动门控；心率不在 45–120 BPM 或 IBI 变异系数 >20% 的窗口被丢弃。

  ### 密钥协商协议
  - 极化码：rate-1/3，N=128，K=42，使用逐次抵消（SC）译码与部分和传播。
  - 节点 A 随机抽取 $m \in \{0,1\}^{42}$，极化编码为 $c$，广播 helper $h = b_A \oplus c$。
  - 节点 B 计算 $r = b_B \oplus h$ 并 SC 译码恢复 $\hat{m}$；若 $\hat{m}=m$ 则成功。
  - 三个成功 block 产生 126-bit 共享密钥材料，再用 SHA-256 压缩为 AES-128 会话密钥。
  - 失败窗口以新的 120 s 块重试。

  ### 硬件实现与验证
  - RTL 模块：定点预处理器、峰值 beat 检测器、IBI 定时器、Gray 量化器、极化编码器、SC 译码器（含部分和传播）、AXI4-Lite 控制接口。
  - 极化编码器：七级蝶形 $F^{\otimes 7}$，固定地址 XOR，8 个时钟周期完成。
  - SC 译码器：顺序逐次抵消调度，在 10 MHz 下约 32,000 个时钟周期完成 N=128 bit 译码。
  - 实现平台：AMD/Xilinx XC7Z020（PYNQ-Z2），Vivado 2025.2，时钟 10 MHz。
  - 验证方式：Python 主机脚本流式送入 15,360 个 16-bit PPG 样本（120 s，128 Hz），触发完整 pipeline，确认 FPGA 输出与软件参考完全一致。

  ## 主要发现与核心结论

  ### 野外多位置性能
  - 节拍检测平均绝对误差（MAE）：25.6–31.2 ms（跨部位）。
  - 原始量化 bit 一致率（raw bit agreement）：86.0%（head–ankle）、87.6%（wrist–ankle）、90.1%（head–wrist）。
  - 原始 bit 错误率：9.9–14.0%。
  - 经极化码纠错后的密钥一致率（key agreement）：51.3%（head–ankle）、55.2%（wrist–ankle）、69.8%（head–wrist）。
  - head–wrist 为最佳配对（90% raw，70% key），head–ankle 最具挑战性（86% raw，51% key）。
  - 失败窗口重试次数：head–wrist 平均 1.4 次，head–ankle 不到 2 次。

  ### 与先验方法对比
  - 在 WildPPG 上重新评估 H2K、FaceFinger、E2P、MagKey、PPG Token：原始 bit 一致率跌至 51.0–61.6%，端到端密钥一致率几乎归零（H2K 0.2%，FaceFinger 0.7%，PPG Token 0.0%）。
  - HHK 是首个在自由生活真实数据上验证、且提供可综合 RTL 的跨位置 PPG 密钥生成系统。

  ### 硬件资源与能耗
  - 综合后资源：18,760 个 LUT，20,971 个 FF。
  - 分模块资源（表 II）：
    - BPF 预处理器：335 LUT / 113 FF
    - Foot 检测器：178 LUT / 84 FF
    - IBI 定时器与量化器：441 LUT / 209 FF
    - 极化编码器与控制：358 LUT / 556 FF
    - SC 译码器：17,076 LUT / 19,359 FF（占 HHK IP 的 92.9% LUT 和 94.4% FF）
    - AXI4-Lite 接口：90 LUT / 265 FF
    - HHK IP 总计：18,378 LUT / 20,508 FF
    - AXI 互连：364 LUT / 426 FF
  - 无乘法器、无 DSP slice、无嵌入式 BRAM。
  - 动态功耗：10 MHz 下 15 mW。
  - 单次密钥生成能耗：15 mW × 3.2 ms = 48 µJ。
  - 在 120 s 采集窗口内平均功耗：0.4 µW。
  - 窗口结束到 key-ready 的延迟：3.2 ms（10 MHz 下 32,000 周期）。

  ### 硅验证
  - FPGA 原型对 head/wrist/ankle 三种位置各产生 128-bit 输出；RTL 仿真与物理芯片输出之间的 XOR 条带完全为白色，即 raw bit string、helper data、reconciliation vector 三者均零 bit 不一致。
  - 120 s head 数据流：硬件 pipeline 检测 90 个 foot point，累积 64 个 IBI，产生 128 个编码 bit，decode_ok=1，恢复出的 msg_hat 与软件参考完全一致。

  ### 额外观察
  - 受试者间差异主要由生理信号多样性而非活动强度驱动：高低表现者的 IMU 运动水平相当。
  - 对 ankle 通道尝试用 onboard IMU 做最小均方（LMS）自适应运动抵消，结果 IBI 时序误差增加 5–14 ms，因线性滤波会扭曲 beat 检测依赖的波形相位，故未采用。

  ## 潜在研究方向

  1. **胸骨（sternum）通道的可靠性**：论文明确排除 sternum，因其在运动下 beat 可见性不足以支持可靠 IBI 提取；如何在强运动下恢复胸骨 PPG 质量仍是开放问题。
  2. **密钥一致率的提升空间**：野外 head–ankle 仅 51.3% key agreement，head–wrist 69.8%，距离实际部署的高可用性仍有差距；需要更鲁棒的跨位置对齐、更好的运动伪影抑制或更强的纠错码。
  3. **自适应运动抵消的副作用**：LMS 滤波反而增加 5–14 ms IBI 误差，说明线性相位失真会损害 beat 检测；非线性或基于形态学的运动抑制值得探索。
  4. **安全分析不足**：论文未量化信息泄漏（helper data 泄露量）、密钥熵、欺骗攻击（如文献 [12] 的液晶调制器）下的鲁棒性，也未评估不同受试者间误匹配率。
  5. **ASIC 迁移与更低功耗**：FPGA 上 48 µJ/0.4 µW 已优于通用处理器，但先进工艺下的面积、泄漏功耗、电压域优化仍需评估；SC 译码器占 92%+ 资源，是优化重点。
  6. **多节点/群组密钥扩展**：当前架构仅处理 A–B 两节点；BAN 通常含多个传感器，如何实现多对多或群组密钥派生未讨论。
  7. **真实临床长期使用**：单数据集、单登山场景、16 名受试者；不同疾病状态、药物、年龄、肤色对 PPG 质量和一致率的影响尚未验证。

  ## 与林赛研究的关联

  直接关联较弱：本组核心方向是高次谐波产生（HHG）、阿秒科学、强场驱动量子物质与量子几何，而非可穿戴生物特征安全。不过可以抽取以下间接接口：

  - **信号处理 pipeline 的可迁移性**：HHK 的“带通→峰值检测→时序对齐→量化→纠错”链路，与我们在强场实验中构建的“单发 HHG 光谱→峰识别→延迟标定→抖动校正→光谱相位恢复”前端触发逻辑在结构上有相似之处；特别是 300 ms 对齐容差、等频分箱和 Gray 码边界软化的思想，对设计强场实验里跨探测器时间戳对齐与低 bit 深度事件触发有参考价值。
  - **硬件轻量化约束**：HHK 坚持无乘法器、无 DSP、无 BRAM 的定点 RTL 实现，对我们未来把光谱诊断前端（如平衡探测、瞬态光栅读出或时频分析）下沉到边缘 FPGA/ASIC 时，提供了面积-功耗基准（48 µJ/event、0.4 µW 平均）和模块占比经验（译码器/状态机占绝对主导）。
  - **真实场景验证的警示**：论文从实验室 90%+ 一致率跌到野外 51–70% 的量化，强烈提示我们在 HHG/阿秒方法论文中也应区分“合成数据/干净实验”与“真实束线噪声、样品抖动、限能条件”下的性能；任何声称的算法增益都应在后者中复测。
  - **交变磁/莫尔体系暂无直接接口**：HHK 与交变磁性（altermagnetism）、莫尔超晶格或量子几何张量没有物理对应；不建议强行建立联系。

## 研究方法（方法卡）
<!-- methods-backfill:v1 -->
**方法**：跨位置 PPG 心率间期密钥生成流水线（可综合 RTL：定点滤波→beat 检测→IBI 对齐→Gray 量化→极化码模糊承诺→SHA-256）

**原理**：两个可穿戴节点从同步采集的 PPG 信号独立推导一致会话密钥（不传输任何秘密）：因果定点 IIR 带通（Q15 定点、无乘法器）→局部最大值 beat 检测（prominence 阈值 + 400 ms 不应期）→300 ms 容差跨位置 IBI 对齐→全数据集四分位 4-bin 等频量化为 2-bit Gray 码（边界跨越最多 1-bit 不一致）→IMU 运动门控（心率 45–120 BPM、IBI 变异系数 >20% 窗口丢弃）→rate-1/3 极化码（N=128，K=42）SC 译码模糊承诺；3 个成功 block 产生 126-bit 密钥材料经 SHA-256 压缩为 AES-128 会话密钥；首次在自由生活真实数据上验证并提供可综合 RTL。
