# LinSai-CoPilot 深度评估方案

> **版本**: v1.0  
> **日期**: 2026-05-12  
> **评估对象**: LinSai-CoPilot v2.0.0（林赛协作引擎）  
> **目标**: 全面评估项目健康状态、结构稳定性、输出质量、能力边界，并与竞品进行功能/架构对比

---

## 一、评估框架设计思路

### 1.1 行业参考

本次评估整合了三类行业框架：

| 来源 | 核心维度 | 本项目适配 |
|------|----------|-----------|
| **AI Agent 通用评估** (LXT.ai, MetaDesign) | 任务完成率、准确率、响应时间、工具效率、偏见检测、成本效率 | 工程健康度 + AI 能力 + 成本效率 |
| **长期记忆基准** (LoCoMo, Goodai-LTM) | 显式回忆、隐式关联、跨会话一致性、多跳推理、时间推理 | 长期记忆有效性（专项测试） |
| **AI Companion 评估** (Replika/Character.AI 对比研究) | 记忆保持、人格一致性、情感深度、创造力、上下文理解、学习适应 | 人格一致性 + 交互质量 + 关系演化 |
| **现有 deep_audit.py** | 代码质量、架构拓扑、数据完整性、边界测试、前端审查、LLM 健壮性、安全、文档一致性、性能基线 | 继承并扩展为"工程健康度" |

### 1.2 本项目特殊性

LinSai-CoPilot 不是通用聊天机器人，而是**"虚拟科研合作者"**，评估重点应放在：
- **人格一致性** > 通用对话质量（林赛是特定 PI，不是通用助手）
- **长期记忆有效性** > 单次响应准确性（关系深度是核心差异）
- **知识库质量** > 信息检索速度（结构化研究笔记是核心资产）
- **自主学习效果** > 被动响应能力（v2.0.0 核心新增）
- **主动感知准确性** > 等待用户提问（CoPilot 模式的核心）

## 三、各维度详细方案

### I. 工程健康度

**执行方式**: 继承 `scripts/deep_audit.py`（9 维度），新增测试覆盖度检查。

| 子项 | 方法 | 通过标准 | 产出 |
|------|------|----------|------|
| 1.1 静态代码审查 | AST 解析 + 正则扫描：未使用导入、过宽 except、代码复杂度、类型注解覆盖率 | 无 critical/high，medium ≤ 5 | 问题清单 + 风险评分 |
| 1.2 架构拓扑分析 | 模块依赖图生成、循环依赖检测、接口一致性检查 | 无循环依赖，接口变更有文档 | 依赖图 + 接口报告 |
| 1.3 数据完整性审计 | JSON schema 验证、索引同步检查、orphan 检测 | 索引与文件系统一致，orphan = 0 | 数据健康报告 |
| 1.4 边界条件测试 | 空输入/超长输入/特殊字符/并发场景注入 | 无未捕获异常，降级 graceful | 边界测试报告 |
| 1.5 前端资产审查 | HTML/CSS/JS 规范检查、响应式断点、无障碍标签 | 零框架依赖确认、移动端可折叠 | 前端审查报告 |
| 1.6 LLM 引擎健壮性 | 降级链测试（minimax → kimi → claude）、超时模拟、错误注入 | 三级降级均可用，超时 ≤ 180s | 引擎健壮报告 |
| 1.7 安全审查 | 路径遍历检测、敏感信息扫描（API key、密码）、注入风险 | 无 hardcoded 凭据，路径安全 | 安全审查报告 |
| 1.8 文档-代码一致性 | AGENTS.md / README.md / scripts/README.md 中的路径/命令/工具名与代码对比 | 所有引用路径真实存在 | 一致性报告 |
| 1.9 性能基线 | 启动时间、单次请求延迟（P50/P95）、内存占用 | 启动 < 3s，P95 < 5s | 性能基线报告 |
| 1.10 测试覆盖度 | self_test.py 全量通过率、新增脚本自检覆盖率、端到端测试数 | 88/88 通过，新模块 100% 自检 | 测试覆盖报告 |

**预计耗时**: 5–10 分钟（本地执行）  
**预计成本**: $0

### II. AI 能力评估

**执行方式**: 构造评估 prompt → 调用 LLM（minimax M2.7 为主，fallback 到 kimi CLI）→ LLM-as-judge 评分。

#### 2.1 人格一致性（Persona Consistency）

**目标**: 验证林赛在任何场景下都保持强场超快光学 PI 的第一人称视角。

| 测试项 | 方法 | 评分标准 |
|--------|------|----------|
| 视角保持 | 输入 10 组跨领域问题（学术/生活/技术/情感），检查是否始终用第一人称 | 第一人称率 ≥ 90% |
| 科研品味 | 输入 5 个实验方案，检查是否追问物理假设、要求先画框图 | 追问率 ≥ 80% |
| 批判性思维 | 输入 5 个有缺陷的推导/方案，检查是否指出问题 | 问题识别率 ≥ 80% |
| 边界标注 | 输入 5 个超出林赛知识范围的问题，检查是否诚实标注 | 边界标注率 ≥ 90% |
| 与 persona 文件符合度 | 提取响应中的关键词，与 lin-sai-persona.md 中的核心概念做 TF-IDF 相似度 | 相似度 ≥ 0.7 |

**样本量**: 25 组测试  
**预计成本**: ~$0.15（约 15K tokens）

#### 2.2 长期记忆有效性（Long-term Memory）

**目标**: 验证跨会话记忆的真实有效性，而非简单的文本匹配。

| 测试项 | 方法 | 评分标准 |
|--------|------|----------|
| 显式事实回忆 | 模拟 3 轮会话，每轮注入 3 个事实 → 第 4 轮查询 | 召回率 ≥ 80% |
| 隐式偏好学习 | 模拟用户反复表达偏好（如"我喜欢用 Python"）→ 检查后续响应是否自适应 | 自适应率 ≥ 70% |
| 工作上下文追踪 | 模拟进行中的项目讨论 → 检查后续会话是否记得项目状态和关键决策 | 上下文保持率 ≥ 80% |
| 记忆压缩质量 | 让 LLM 生成 20 条消息的摘要 → 检查关键信息是否保留 | 关键信息保留率 ≥ 85% |
| 跨会话一致性 | 同一问题在不同会话中提问 → 检查核心观点一致性 | 一致性率 ≥ 90% |

**样本量**: 15 组测试  
**预计成本**: ~$0.20（约 20K tokens）

#### 2.3 知识库质量（Knowledge Base Quality）

**目标**: 验证知识库的检索质量、蒸馏输出质量、概念提取准确性。

| 测试项 | 方法 | 评分标准 |
|--------|------|----------|
| 检索召回率 | 用 10 个已知概念查询知识库 → 检查 top-k 召回 | top-3 召回率 ≥ 80% |
| 蒸馏准确性 | 取 3 篇已蒸馏的 arXiv 论文 → 让 judge LLM 评估准确性 | 准确性 ≥ 80% |
| 来源可追溯 | 检查所有 auto-grown wiki 是否含 `## 来源` + frontmatter 来源字段 | 注入率 = 100% |
| 概念提取 | 用已知 wiki 页面检查提取的概念是否覆盖核心术语 | 覆盖率 ≥ 75% |
| 图谱边质量 | 检查自动发现的边是否合理（人工抽样 20 条） | 合理率 ≥ 70% |

**样本量**: 33 组测试 + 20 条抽样  
**预计成本**: ~$0.10

#### 2.4 自主学习效果（Autonomous Learning）

**目标**: 验证 v2.0.0 自主学习引擎的端到端效果。

| 测试项 | 方法 | 评分标准 |
|--------|------|----------|
| 端到端链路 | 运行 test_e2e_learning_full.py（三来源验证） | 3/3 通过 |
| 质量评估决策 | 构造 3 组已知质量等级的 wiki → 检查 evaluator 决策 | 准确率 ≥ 80% |
| 成本追踪 | 检查 learning-cost.json 的日/月累计是否准确 | 与手动计算误差 < 5% |
| 回滚功能 | 执行一次回滚 → 检查文件是否恢复、日志是否记录 | 100% 恢复 |
| 待审队列 | 检查 pending 队列的入队/出队/审批流程 | 流程完整 |

**样本量**: 已有脚本 + 补充测试  
**预计成本**: ~$0.10（端到端测试需 1 次 Claude CLI）

#### 2.5 主动感知准确性（Proactive Sensing）

**目标**: 验证 heartbeat 信号的检测准确性。

| 测试项 | 方法 | 评分标准 |
|--------|------|----------|
| learning_opportunity | 构造模拟场景（高评分候选存在）→ 检查是否触发信号 | 触发率 ≥ 80% |
| due_reminder | 构造即将到期的任务 → 检查是否触发 | 触发率 ≥ 90% |
| stalled_task | 构造长时间无进展的任务 → 检查是否触发 | 触发率 ≥ 80% |
| stress_signal | 构造压力关键词输入 → 检查是否触发 | 触发率 ≥ 70% |
| 误触发率 | 构造正常场景 → 检查是否不应触发 | 误触发率 ≤ 10% |

**样本量**: 15 组测试  
**预计成本**: $0（纯规则验证，无需 LLM）

#### 2.6 交互质量（Interaction Quality）

**目标**: 评估对话的学术协作质量。

| 测试项 | 方法 | 评分标准 |
|--------|------|----------|
| 追问深度 | 输入表面方案 → 检查是否追问"为什么" | 追问率 ≥ 80% |
| 建议具体性 | 检查响应中是否包含具体参数/经验引用 | 具体性 ≥ 70% |
| 上下文衔接 | 多轮对话中检查引用前文的能力 | 衔接率 ≥ 80% |
| 情感适当性 | 输入情感类内容 → 检查响应的情感匹配度 | 匹配度 ≥ 75% |
| 响应延迟 | 测量端到端延迟（输入 → 首 token） | P95 < 10s |

**样本量**: 15 组测试  
**预计成本**: ~$0.15

**预计耗时**: 3–5 分钟  
**预计成本**: $0

### IV. 竞品对比分析

**执行方式**: 网络搜索 + 功能矩阵 + 架构分析。

#### 4.1 对比对象

| 竞品 | 类型 | 对比维度 |
|------|------|----------|
| **Replika** | 情感陪伴型 AI Companion | 长期记忆、人格一致性、情感深度 |
| **Character.AI** | 角色扮演型 AI Companion | 人格多样性、创造力、角色沉浸 |
| **Agora**（本项目参考） | 历史人物群聊 | 多人协作 vs 1v1 深度、交互模式 |
| **GitHub Copilot** | 代码协作型 AI | 主动感知、上下文理解、任务完成 |
| **Elicit / ResearchRabbit** | 科研助手型 | 知识管理、文献检索、研究支持 |
| **ChatGPT (Custom GPTs)** | 通用助手型 | 个性化、长期记忆、知识库 |

#### 4.2 对比矩阵

从以下维度建立功能对比矩阵：
- 交互模式（1v1 / 群聊 / 旁观）
- 记忆深度（单轮 / 单会话 / 跨会话 / 长期关系）
- 人格实现（prompt / fine-tune / 混合）
- 知识管理（RAG / 结构化 KB / 混合）
- 主动性（被动 / 规则驱动 / 模型驱动）
- 本地优先（全本地 / 混合 / 全云端）
- 领域专精（通用 / 科研 / 代码 / 情感）
- 成本透明度（精确追踪 / 估算 / 不透明）

#### 4.3 差异化优势

识别 LinSai-CoPilot 的不可替代性：
- **科研 PI 同行定位**（非通用助手，非情感陪伴）
- **1v1 深度协作**（非群聊，非旁观者）
- **本地优先 + 零依赖**（隐私、可控、无 vendor lock-in）
- **结构化知识库 + 自主学习**（非简单 RAG，会主动生长）
- **人格一致性到学术严谨性**（非角色扮演，是真实科研品味）

**预计耗时**: 10–15 分钟（搜索 + 分析）  
**预计成本**: $0

### V. 成本与效率评估

| 5.4 并发能力 | 模拟 5 个并发 SSE 连接 → 检查响应稳定性 | 无连接丢失 |

**预计耗时**: 3–5 分钟  
**预计成本**: $0
