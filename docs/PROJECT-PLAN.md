# 林赛协作引擎 — 项目总策划案

> **文档定位**：项目级战略蓝图。供项目负责人（首席代理）统筹全局、分配任务、验收成果。
> **版本**：v1.0
> **日期**：2026-05-08
> **状态**：策划阶段

---

## 一、项目愿景与核心目标

### 1.1 一句话定义

构建一个**以林赛（Lin Sai）为独立人格实体的1对1虚拟合作者系统**，让用户拥有一位"记得一切、理解上下文、主动参与、共同成长"的专属AI协作者。

### 1.2 核心目标（按优先级排序）

| 优先级 | 目标 | 衡量标准 |
|--------|------|----------|
| P0 | **人格一致性**：林赛的响应始终符合其人格锚点 | 人格一致性测试通过率 ≥ 90% |
| P0 | **记忆持续性**：跨会话保持用户相关信息 | 用户画像关键信息 recall ≥ 80% |
| P0 | **对话完整性**：聊天记录全文持久化 | 消息零丢失，可回溯任意历史会话 |
| P1 | **自主感知能力**：基于记忆主动发起交互 | 主动提醒命中率 ≥ 60%（用户认为"有用"） |
| P1 | **自我成长**：从交互中学习并更新自身 | 用户画像准确度随会话数增加而提升 |
| P2 | **多模态协作**：支持文档、代码、任务追踪 | 基础文件解析与任务CRUD完整可用 |
| P2 | **Agora集成**：可召唤历史人物群聊 | 与Agora系统的协议对接完成 |

### 1.3 关键约束（不可妥协）

- **零第三方依赖**：仅使用Python 3标准库
- **本地优先**：所有数据仅存本地文件系统，无云端上传
- **单向资产流**：virtu-LinSai → LinSai-CoPilot，禁止反向修改
- **人格锚点不可变**：姓名、身份、家庭、核心信条、人格五维冻结
- **上下文预算**：单次LLM调用注入内容总计 ≤ 30000字符（约7500-10000 tokens，远低于Kimi 256K tokens上限）

## 二、项目分解（WBS）

采用**功能模块 × 开发阶段**的矩阵式分解。

### 2.1 功能模块总览

```
LinSai-CoPilot
├── M1: 人格引擎（Persona Engine）
│   └── 人格注入、风格一致性控制、人格演进边界
├── M2: 会话系统（Session System）
│   └── 创建、加载、存档、消息日志、状态管理
├── M3: 记忆系统（Memory System）
│   └── 短期上下文、中期摘要、长期记忆、记忆压缩、检索
├── M4: 上下文构建器（Context Builder）
│   └── Prompt组装、优先级排序、预算控制、动态裁剪
├── M5: 核心引擎（CoPilot Engine）
│   └── LLM调用、响应解析、流式输出、错误恢复
├── M6: 主动感知（Proactive Sense）
│   └── 心跳检测、任务追踪、压力信号、提醒机制
├── M7: 任务管理（Task Manager）
│   └── CRUD、状态流转、截止日期追踪、与记忆联动
├── M8: 用户界面（User Interface）
│   └── CLI交互、命令解析、富文本渲染
├── M9: 文档与代码协作（Document & Code）
│   └── 文件解析、论文阅读、代码分析、参考文献管理
└── M10: 外部集成（External Integration）
    └── Agora协议、多设备同步、语音接口
```

### 2.3 详细工作分解（Phase 1-4）

#### Phase 1：启明（MVP）— 2周

**WBS 1.1 会话管理（session_manager.py）**
- 1.1.1 会话目录创建：`sessions/YYYYMMDD-主题/`
- 1.1.2 会话列表与查询：列出所有会话、按日期/主题搜索
- 1.1.3 会话加载与续接：读取messages.json继续对话
- 1.1.4 会话归档：标记完成、移动到归档目录
- 1.1.5 会话元数据管理：state.json读写（主题、模式、时间戳）

**WBS 1.2 消息系统（messages.json）**
- 1.2.1 消息结构定义：msg_id, role, content, timestamp, mode
- 1.2.2 消息追加与持久化：原子写入、异常恢复
- 1.2.3 消息检索：按时间范围、关键词过滤
- 1.2.4 消息导出：Markdown格式导出单会话

**WBS 1.3 上下文构建器（context_builder.py）**
- 1.3.1 人格注入加载：读取lin-sai-persona.md
- 1.3.2 会话历史组装：最近N条消息，字符预算控制
- 1.3.3 动态预算分配：系统指令/记忆/上下文/历史/输入的比例控制
- 1.3.4 字符数统计与裁剪：按优先级截断，确保≤30000字符，支持紧急模式临时扩展至50000字符

**WBS 1.4 核心引擎（copilot_engine.py）**
- 1.4.1 LLM调用适配：Kimi CLI / Claude CLI subprocess封装
- 1.4.2 响应解析：提取回复内容、处理流式输出
- 1.4.3 错误处理：超时、空响应、CLI未安装、速率限制
- 1.4.4 对话循环：接收输入→构建上下文→调用LLM→解析响应→记录消息
- 1.4.5 启动参数解析：--start, --continue, --list, --help

**WBS 1.5 CLI界面**
- 1.5.1 交互式对话循环：提示符、多行输入、退出命令
- 1.5.2 命令系统：/save, /mode, /summary, /exit
- 1.5.3 富文本渲染：Markdown基本格式在终端的展示
- 1.5.4 启动画面与状态显示：当前会话信息、模式标识

**WBS 1.6 人格一致性保障**
- 1.6.1 系统Prompt模板：人格注入 + 当前模式指令
- 1.6.2 响应风格校验：短句主导、物理隐喻、元认知信号检测
- 1.6.3 人格边界保护：拒绝修改人格锚点的请求

#### Phase 2：长河 — 3周

**WBS 2.1 用户画像（memory/user-profile.json）**
- 2.1.1 画像结构设计：偏好、习惯、已知技能、研究领域、沟通风格
- 2.1.2 画像提取：从对话中自动识别用户特征（基于规则+LLM辅助）
- 2.1.3 画像更新：增量更新、冲突解决、置信度标记
- 2.1.4 画像注入：将画像摘要加入上下文构建流程

**WBS 2.2 工作上下文（memory/working-context.json）**
- 2.2.1 项目追踪结构：进行中的项目、关键决策、待办事项
- 2.2.2 上下文提取：识别对话中的项目提及和决策点
- 2.2.3 上下文同步：与tasks/active/目录的双向联动
- 2.2.4 上下文注入：当前项目摘要加入Prompt

**WBS 2.3 长期记忆索引（memory/long-term-memory.json）**
- 2.3.1 记忆片段结构：触发词、摘要、来源会话、时间戳、重要性
- 2.3.2 记忆创建规则：名言、关键事件、重要决策、用户偏好
- 2.3.3 记忆检索：关键词匹配 + 简单向量相似度（基于标准库实现）
- 2.3.4 记忆去重与合并：相似记忆合并、冲突检测

**WBS 2.4 记忆压缩**
- 2.4.1 会话摘要生成：超过20条消息后触发LLM摘要
- 2.4.2 摘要结构：主题、关键决策、待办事项、情感基调
- 2.4.3 跨会话整合：每10次会话触发长期记忆整合
- 2.4.4 摘要存储：summary.md与messages.json关联

**WBS 2.5 记忆片段管理（memory/snippets/）**
- 2.5.1 片段文件格式：独立Markdown文件，YAML Front Matter元数据
- 2.5.2 片段索引：snippets/index.json维护检索目录
- 2.5.3 片段生命周期：创建、更新、过期（90天TTL）

**WBS 2.6 任务管理（task_manager.py）**
- 2.6.1 任务CRUD：创建、读取、更新、删除任务文件
- 2.6.2 任务状态流转：backlog → active → completed，支持暂停
- 2.6.3 任务模板：研究任务、写作任务、实验任务、提醒事项
- 2.6.4 任务与记忆联动：任务更新触发工作上下文更新
- 2.6.5 截止日期追踪：日期解析、逾期检测、提前提醒

#### Phase 3：觉醒 — 3周

**WBS 3.1 心跳机制（heartbeat）**
- 3.1.1 心跳触发器：定时扫描（模拟cron，基于文件时间戳）
- 3.1.2 扫描目标：任务截止日期、会话最后活跃时间、用户状态信号
- 3.1.3 心跳频率配置：默认每日一次，可配置
- 3.1.4 心跳日志：记录检测到的信号和处理动作

**WBS 3.2 主动提醒**
- 3.2.1 提醒触发条件：截止日期前N天、任务长时间无进展
- 3.2.2 提醒内容生成：引用相关上下文，生成温和提醒文案
- 3.2.3 提醒输出方式：CLI启动时显示、写入通知文件
- 3.2.4 用户反馈处理："现在不想聊"→退回被动模式并记录

**WBS 3.3 压力信号检测**
- 3.3.1 信号词库：失眠、疲惫、麻木、焦虑、拒稿、延期等
- 3.3.2 检测规则：关键词匹配 + 频率统计（近7天出现次数）
- 3.3.3 响应策略：元认知引导、经验映射、边界尊重
- 3.3.4 隐私保护：压力信号仅本地记录，不上传

**WBS 3.4 自主级别控制**
- 3.4.1 三级自主模型：
  - `observe`（观察）：仅记录，不行动
  - `suggest`（建议）：提醒用户但不代劳（默认）
  - `act`（行动）：直接执行任务（需用户显式授权）
- 3.4.2 模式切换：用户命令切换、上下文感知自动建议
- 3.4.3 行动审计：所有自主行动记录日志，用户可审查

**WBS 3.5 交互模式自动识别**
- 3.5.1 模式分类器：基于用户输入判断当前模式
  - `co-working`：包含任务关键词、请求协助推进
  - `deep-talk`：情感信号、困惑表达、人生问题
  - `quick-check`：简短问题、是/否询问、量纲检查
- 3.5.2 模式切换：自动建议或用户显式切换
- 3.5.3 模式历史：记录模式演变，用于理解用户习惯

## 三、颗粒度划分

### 3.1 颗粒度原则

| 层级 | 粒度 | 交付物 | 负责角色 |
|------|------|--------|----------|
| 阶段（Phase） | 2-4周 | 可演示的功能集合 | 首席代理（我） |
| 模块（Module） | 3-7天 | 独立可测的脚本/功能 | 模块代理 |
| 任务（Task） | 1-2天 | 具体函数/类/接口 | 子代理 |
| 子任务（Sub-task） | 2-4小时 | 单一函数或测试用例 | 子代理 |

### 3.2 最小交付单元定义

每个子任务必须满足：
1. **可独立验证**：有明确的输入/输出，可运行测试
2. **可回滚**：失败时不破坏其他模块
3. **可文档化**：CHANGELOG.md中一行可描述
4. **字符可控**：代码量≤500行（超过则拆分）

### 3.3 文件级颗粒度规范

```
scripts/
├── session_manager.py      # ≤400行：会话CRUD + 目录操作
├── memory_manager.py       # ≤500行：记忆读写 + 压缩 + 检索
├── task_manager.py         # ≤400行：任务CRUD + 状态流转
├── copilot_engine.py       # ≤500行：LLM调用 + 响应解析 + 主循环
├── context_builder.py      # ≤400行：Prompt组装 + 预算控制
├── proactive_engine.py     # ≤400行：心跳 + 提醒 + 信号检测
├── document_handler.py     # ≤400行：文件解析 + 摘要（Phase 4）
└── __init__.py             # 模块导出
```

> **约束**：任何脚本超过500行必须拆分为子模块。保持文件小巧 = 降低认知负荷 = 提高子代理并行效率。

## 四、项目管理策略

### 4.1 代理组织架构

```
首席代理（Project Lead）
├── 架构代理（Architect Agent）
│   └── 负责：接口设计、数据结构设计、跨模块协调
├── 模块代理组（Module Agents）
│   ├── 会话模块代理
│   ├── 记忆模块代理
│   ├── 引擎模块代理
│   ├── 任务模块代理
│   └── 主动感知代理
├── 质量代理（QA Agent）
│   └── 负责：测试用例、人格一致性测试、代码审查
└── 文档代理（Docs Agent）
    └── 负责：CHANGELOG、README更新、AGENTS.md维护
```

### 4.2 任务分配协议

1. **任务领取**：首席代理将任务写入 `tasks/active/任务名.json`
2. **代理执行**：子代理读取任务文件，完成后更新状态
3. **成果提交**：子代理提交代码 + 自检报告
4. **验收流程**：首席代理运行测试 → 通过则合并 → 更新CHANGELOG

### 4.3 任务文件格式

```json
{
  "task_id": "T1.1.1",
  "title": "会话目录创建",
  "phase": "Phase 1",
  "module": "session_manager",
  "assignee": "coder-agent-1",
  "status": "in_progress",
  "priority": "P0",
  "acceptance_criteria": [
    "根据主题和日期创建目录 sessions/YYYYMMDD-主题/",
    "目录已存在时返回已有会话ID",
    "非法字符在主题中被安全处理"
  ],
  "dependencies": [],
  "estimated_hours": 4,
  "started_at": "2026-05-08T10:00:00Z",
  "completed_at": null,
  "notes": ""
}
```

### 4.4 沟通机制

| 场景 | 机制 | 位置 |
|------|------|------|
| 任务分配 | 任务JSON文件 | tasks/active/ |
| 进度同步 | 任务状态更新 | tasks/active/ 中的status字段 |
| 阻塞升级 | 任务notes字段标注阻塞原因 | tasks/active/ |
| 跨模块协调 | 架构代理审阅接口 | AGENTS.md + 代码审查 |
| 验收结果 | CHANGELOG.md + 任务移至completed/ | CHANGELOG.md |

### 4.5 冲突解决

1. **接口冲突**：架构代理裁决，优先保证向后兼容
2. **资源冲突**：首席代理调度，同一文件同时只能被一个代理修改
3. **设计分歧**：回归AGENTS.md和本策划案的原始定义
4. **人格一致性争议**：以 `persona/lin-sai-persona.md` 为最终权威

## 五、项目维护策略

### 5.1 版本管理

- **版本号格式**：`v{Phase}.{迭代}.{补丁}`
  - Phase：对应开发阶段（0-5）
  - 迭代：每个阶段内的迭代次数
  - 补丁：Bug修复
- **示例**：v1.2.1 = Phase 1第2迭代第1补丁

### 5.2 变更控制

所有变更必须经过：
1. **变更申请**：子代理在任务notes中说明变更范围
2. **影响评估**：架构代理评估对现有模块的影响
3. **实施变更**：子代理在独立分支/任务中实施
4. **回归测试**：QA代理运行全量测试
5. **文档更新**：文档代理同步更新AGENTS.md和CHANGELOG

### 5.3 记忆系统维护

| 维护任务 | 频率 | 自动化程度 |
|----------|------|------------|
| 会话摘要生成 | 每会话>20条消息 | 全自动 |
| 长期记忆整合 | 每10次会话 | 半自动（LLM生成+人工审阅） |
| 记忆片段TTL清理 | 每日 | 全自动（删除>90天未引用片段） |
| 用户画像更新 | 每5次会话 | 半自动 |
| 存储用量检查 | 每周 | 全自动（告警阈值：100MB） |

### 5.4 人格资产同步

- **同步源**：virtu-LinSai项目
- **触发条件**：virtu-LinSai发布新版本 + 维护者评估有必要
- **同步流程**：
  1. 维护者评估上游变更对本项目的影响
  2. 复制新版本到 `persona/` 目录
  3. 更新 `source-manifest.json`

## 八、资源限制与风险管控

### 8.1 LLM调用限制

| 限制项 | 约束 | 应对策略 |
|--------|------|----------|
| 速率限制 | Kimi/Claude CLI有调用频率限制 | 本地缓存响应、后台任务异步执行、指数退避重试 |
| 上下文窗口 | 30000字符注入预算（项目设定） | 动态预算分配、摘要压缩、分层检索；远低于Kimi 256K tokens上限 |
| 调用成本 | 每次调用消耗Token | 批量处理后台任务、缓存常用上下文、避免冗余调用 |
| 可用性 | CLI可能未安装或配置错误 | 启动时检测、优雅降级（提示用户安装）、离线模式 |

### 8.2 存储资源限制

| 限制项 | 约束 | 应对策略 |
|--------|------|----------|
| 磁盘空间 | 假设用户环境≤10GB可用 | 自动压缩历史会话、90天TTL清理、大文件引用而非复制 |
| 文件数量 | 大量小文件影响性能 | 按月份归档、索引文件汇总 |
| I/O性能 | 频繁读写导致卡顿 | 批量写入、异步持久化、内存缓存 |

### 8.3 计算资源限制

| 限制项 | 约束 | 应对策略 |
|--------|------|----------|
| 纯标准库 | 无numpy/pandas等 | 自行实现简单向量相似度（TF-IDF）、不使用embedding模型 |
| 无向量数据库 | 无法使用Qdrant/Pinecone | 基于关键词+简单统计的记忆检索，精确度换 simplicity |
| 无多线程 | Python GIL限制 | 以单进程顺序处理为主，后台任务用subprocess分离 |

### 8.4 风险登记册

| 风险ID | 风险描述 | 概率 | 影响 | 缓解措施 |
|--------|----------|------|------|----------|
| R1 | LLM CLI接口变更导致调用失败 | 中 | 高 | 封装适配层，隔离CLI差异；支持多CLI回退 |
| R2 | 记忆量增长导致上下文溢出 | 高 | 高 | 强制30000字符预算；超限自动触发摘要压缩；分层检索 |
| R3 | 人格一致性随功能增加退化 | 中 | 高 | 人格一致性测试作为门禁；每次变更必须跑测试 |
| R4 | 多代理并行修改导致文件冲突 | 高 | 中 | 文件级锁机制；每个代理独立任务文件；合并时人工审查 |
| R5 | 用户数据丢失（磁盘故障等） | 低 | 高 | 定期导出备份脚本；JSON文件纯文本可手动恢复 |

### 附录C：上下文预算分配（30000字符预算）

```
系统指令（人格注入）      :  8000字符  (27%)  ← 可加载完整人格文件
长期记忆（用户画像+片段） :  6000字符  (20%)  ← 支持更多记忆片段
工作上下文（当前项目）    :  4000字符  (13%)  ← 多项目并行追踪
会话历史（最近消息）      : 10000字符  (33%)  ← 约20-30轮完整对话
当前输入（用户消息）      :  2000字符   (7%)  ← 长论文片段/多段输入
───────────────────────────────────────
合计                      : 30000字符 (100%)
预留 LLM 响应空间         : ~2000-4000 tokens
───────────────────────────────────────
总计使用                  : ~12000-14000 tokens（仅占 256K 的 5%）
```

> **动态调整规则**：
> 1. 当某层无内容时，按比例分配给有内容的层
> 2. 会话历史层可切换为"摘要模式"（压缩过往对话）或"全文模式"（保留最近N轮）
> 3. 紧急情况下（如分析长论文），可临时上调总预算至 50000 字符，但需记录使用情况
> 4. 若检测到上下文接近阈值，自动触发摘要压缩，释放空间
